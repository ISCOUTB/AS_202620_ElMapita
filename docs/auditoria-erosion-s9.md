# Auditoría de erosión arquitectónica — S9 (2026-10-04)

Alcance: límites de contexto entre módulos del backend (`mapas`, `pois`, `auth`, `ubicacion`) y propiedad de los datos, contra lo decidido en [ADR-0001](adr/0001-estilo-arquitectonico-propuesto.md) / [ADR-0005](adr/0005-reemplazo-adr-0001-estilo-arquitectonico.md) (Monolito Modular, DEC-02 desacoplo de Supabase). Método: lectura de código y ejecución de `npx tsc --noEmit`, `npm run test:contracts` y de la API desplegada. Solo se listan hallazgos verificados.

| # | Hallazgo | Ubicación | Severidad | Corrección propuesta |

| 1 | **Cada módulo accede al mismo cliente Supabase global con la `service_role` key**, que ignora RLS. Nada impide que `pois` lea las tablas de `mapas` (`edificios`, `pisos`) o viceversa: la propiedad de datos es solo convención. | `backend/src/shared/supabase/client.ts` (singleton); usado en `mapas/infrastructure/persistence/supabase-repositories.ts:46,101`, `mapas/infrastructure/storage/supabase-storage.ts:13`, `pois/infrastructure/supabase-poi-repository.ts:31`, `auth/infrastructure/supabase/supabase-auth-client.ts:18` | Alta | Declarar propiedad: `mapas` = `edificios`,`pisos`,bucket de modelos; `pois` = `pois`; `auth` = usuarios. | 2 | **Tipo `FloorId` duplicado** en dos contextos.
